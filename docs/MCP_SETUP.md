# MCP — חיבור עוזר AI לנתוני התקציב

מה זה: שרת MCP מקומי שנותן לעוזר AI (Claude, Gemini) **לקרוא** את נתוני התקציב
שלך ולענות עליהם בשפה חופשית — בלי להעלות שום דבר לאינטרנט, ובלי יכולת לשנות
נתונים.

הקובץ: `myfinance/server/mcp/server.js`

---

## מה אפשר לשאול אחרי החיבור

- "כמה כסף יש לנו עכשיו ומה החיוב הקרוב של הכרטיסים?"
- "על מה הוצאנו הכי הרבה באוקטובר?"
- "מצא לי את כל החיובים של סופר פארם בחצי שנה האחרונה"
- "האם אנחנו בתוך התקציב החודש?"
- "למה חסר לנו כסף בחודשים האחרונים? זה קבוע או התנהגותי?"
- "אילו תשלומים (קרדיט) עוד רצים ומתי הם נגמרים?"

העוזר מקבל את אותם מספרים שמופיעים במסכי האפליקציה — אותם כללי הכללה בדיוק
(רק התחברויות וכרטיסים שמסומנים "נכלל בחישוב", בלי העברות פנימיות ובלי קטגוריות
מוחרגות), כך שמה שהוא אומר מתיישב עם מה שרואים על המסך.

---

## אבטחה — חשוב לקרוא פעם אחת

**מה השרת *לא* יכול לעשות:**
- לא יכול לכתוב, לשנות או למחוק כלום. הקובץ נפתח במצב `readOnly` — SQLite עצמו
  חוסם כתיבה, לא רק הקוד.
- לא קורא את טבלת ההתחברויות המוצפנת (`accounts.credentials`). סיסמאות הבנק
  ושמות המשתמש לא נגישים לשום כלי כאן.
- לא מסנכרן, לא פותח דפדפן ולא מתחבר לבנק.

**מה כן צריך לדעת:**
1. **השרת עוקף את מסך הנעילה של האפליקציה.** באפליקציה הנתונים מוגנים בסיסמה;
   כאן העוזר קורא ישר מקובץ ה-DB. מי שיש לו גישה למחשב שלך ולעוזר שמחובר —
   רואה את הנתונים. זאת הסיבה שכדאי לחבר רק עוזרים שרצים על המחשב הזה.
2. **הנתונים מגיעים לענן של ספק ה-AI רק כששואלים שאלה.** השרת לא שולח כלום
   מעצמו, אבל ברגע שהעוזר קורא לכלי — התשובה (מספרים, שמות בתי עסק) נשלחת
   לשרתי Anthropic / Google בתוך השיחה, בדיוק כאילו הדבקת אותם בצ'אט בעצמך.
   אם זה לא מתאים — אל תחבר.
3. אין כאן אסימונים (tokens), מפתחות API או הרשמה. התקשורת היא stdin/stdout בין
   שתי תוכנות על אותו מחשב.

לכל השילובים צריך את שני הנתיבים האלה (כבר מותאמים למחשב הזה):

| מה | נתיב |
|----|------|
| node | `C:/Program Files/nodejs/node.exe` |
| השרת | `C:/Projects/MyBudgetManagement/myfinance/server/mcp/server.js` |

בקבצי JSON משתמשים ב-`/` ולא ב-`\` (ב-JSON הסלאש ההפוך הוא תו בריחה ושובר את
הקובץ). כדאי לציין את הנתיב המלא ל-node ולא רק `node`, כי תוכנות שמריצות שרתי
MCP לא תמיד מקבלות את ה-PATH המלא של המשתמש.

### 1. Claude Desktop

**הדרך הקלה — סקריפט.** סגור את Claude Desktop לגמרי (כולל האייקון במגש
המשימות ליד השעון — לחיצה ימנית → Quit; סגירת החלון לא מספיקה), ואז הרץ
בלחיצה כפולה:

```
scripts\add-mcp-to-claude-desktop.bat
```

הסקריפט מוצא בעצמו את node ואת קובץ ההגדרות, מגבה אותו, מוסיף רק את הבלוק של
`mybudget` ומשאיר כל השאר כמו שהיה. אפשר להריץ אותו פעמיים — אם השרת כבר שם הוא
לא כותב כלום. בסוף פתח את Claude Desktop; הכלים של `mybudget` צריכים להופיע
בתפריט הכלים בשיחה.

**למה סקריפט ולא עריכה ידנית?** Claude Desktop שומר את `mcpServers` *באותו
קובץ* שבו הוא שומר את ההעדפות שלו (תיקיות מאושרות, מצבי הרשאות וכו'), והוא
כותב את הקובץ הזה מהזיכרון בזמן שהוא רץ. עריכה שנעשית כשהאפליקציה פתוחה
נמחקת בשקט כשהיא נסגרת — זה נבדק כאן וקרה בפועל. לכן: לערוך רק כשהאפליקציה
סגורה.

### 2. Claude Code (בתיקיית הפרויקט)

בשורש הפרויקט יש קובץ `.mcp.json` שמוגדר כבר. כשתפתח Claude Code בתיקיית

בדיקה: `/mcp` בתוך Claude Code מציג את השרתים המחוברים.

### 3. Gemini CLI

ערוך את הקובץ (אם אינו קיים — צור אותו):


תוכן:

הפעל מחדש את `gemini` ובדוק עם הפקודה `/mcp`.

שים לב: Gemini CLI עצמו דורש התחברות לחשבון Google או מפתח API — זה לא קשור
לשרת, זאת דרישה של הכלי.

### 4. ChatGPT — לא מומלץ כאן

ChatGPT מתחבר רק לשרתי MCP **מרוחקים** דרך HTTPS; הוא דוחה כתובות localhost.
כדי לחבר אותו היית צריך לחשוף את שרת התקציב לאינטרנט (tunnel / דומיין + אישור
SSL) ולהוסיף הרשאות. בשביל נתונים פיננסיים פרטיים זה סיכון שלא מצדיק את התועלת,
ולכן לא מימשנו את זה. אם בכל זאת תרצה — אפשר להוסיף transport של HTTP עם
אימות, זה שינוי נפרד.

## הכלים שהשרת חושף

| כלי | מה הוא מחזיר | פרמטרים |
|-----|---------------|---------|
| `list_accounts` | כל התחברות וכרטיס: יתרה (בנקים) או חיוב קרוב (כרטיסים), בעלים, מספר תנועות, מתי סונכרן, והאם נכלל בחישוב | — |
| `upcoming_card_charges` | החיוב הקרוב של כל כרטיס בנפרד + הסך הכולל, כולל התאריכים | — |
| `net_balance` | יתרת הבנקים הנכללים + כמה כסף הכרטיסים עומדים לקחת | — |
| `monthly_summary` | הכנסות/הוצאות/פער לכל אחד מ-N החודשים האחרונים (החודש הנוכחי מסומן `partial`) | `months` |
| `category_breakdown` | הוצאות לפי קטגוריה בטווח תאריכים, מהגדולה לקטנה, עם אחוז מהסך | `from`, `to`, `limit` |
| `search_transactions` | חיפוש תנועות בטקסט חופשי / קטגוריה / תאריכים | `text`, `category`, `from`, `to`, `limit`, `all_accounts` |
| `budget_status` | תקציב מול ביצוע לחודש, כולל יתרת המעטפה המצטברת | `month` |
| `insights` | הניתוח של עמוד התובנות: חודש מייצג, מבנה ההוצאה, מה מייצר את הפער, ריאליות התקציב, מגמה, הוצאות תקופתיות ועומס תשלומים | `monthsBack` |

כל הכלים מסומנים `readOnlyHint: true` בפרוטוקול, כך שהעוזר יודע מראש שאין כאן
פעולה שמשנה משהו.

## פתרון תקלות

**השרת לא מופיע ברשימה / "failed to start"**
בדוק שהנתיבים קיימים ושמשתמשים ב-`/`. אפשר להריץ ידנית כדי לראות את השגיאה:

```bash
node C:/Projects/MyBudgetManagement/myfinance/server/mcp/server.js
```

התגובה הנכונה היא שורה אחת `MyBudget MCP ready (read-only): ...` ואז שתיקה
(השרת מחכה להודעות בפרוטוקול). עצור עם Ctrl+C.

**"database not found"**
האפליקציה עוד לא רצה פעם אחת על המחשב הזה, או שהנתונים בתיקייה אחרת. הפעל את
האפליקציה פעם אחת, או הגדר `MYFINANCE_DATA_DIR` באותה הגדרה שבה הוספת את השרת.

**"database is locked"**
האפליקציה סנכרנה בנק באותו רגע והחזיקה את הקובץ. השרת מחכה עד 5 שניות; פשוט
שאל שוב.

**המספרים לא זהים למסך**
ודא שהעוזר קרא לכלי ולא ניחש. אם הוא השתמש ב-`monthly_summary` לחודש הנוכחי —
הוא חלקי מעצם הגדרתו (`partial: true`).

## למפתח (או ל-Claude בעתיד)

- `server/mcp/tools.js` — הפונקציות עצמן, כל אחת מקבלת `db` במפורש וקוראת בלבד.
  כאן נמצא הקבוע `COUNTED` שמחזיק את כלל "מה נספר" המשותף לכל הכלים.
- `server/mcp/server.js` — עטיפת MCP: רישום הכלים, סכימות zod, המרת שגיאה
  להודעה קריאה. **אסור להדפיס ל-stdout** בקובץ הזה — שם עובר הפרוטוקול; לוגים
  נכתבים ל-stderr (`console.error`).
- `tests/test_mcp_tools.js` — בדיקות על DB בזיכרון.
- הוספת כלי חדש: פונקציה טהורה ב-`tools.js` + `tool(...)` ב-`server.js`.
  התיאור של הכלי הוא מה שמנחה את העוזר מתי להשתמש בו — כדאי לכתוב אותו בפירוט.
